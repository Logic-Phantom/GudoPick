# COMPOSITION_ALGORITHM — 구도 엔진

코드: `src/domain/composition/`, `src/domain/preferences/profile-factory.ts`
정책 상수: `composition-policy.ts` 한 곳에서만 조정한다.

> 아래 수치는 **초기 내부 기준**이다. 실기기에서 측정·조정하지 않았다(미검증).

## 1. 좌표 규약

1. 네이티브 detector 결과 = "똑바로 세운 프레임" 기준 0..1 (`VisionDetection`).
   - Android: ML Kit에 `rotationDegrees`를 넘기면 회전 적용 좌표를 돌려준다.
   - iOS: 버퍼 좌표를 받아 `orientation`에 따라 회전(`rotateToUpright`와 같은 수식). **미검증**.
2. 프레임 → 프리뷰 뷰: `mapFrameRectToView` — aspect-fill(cover)/fit(contain) 스케일, 가운데 정렬 오프셋, 전면 카메라 좌우 반전.
3. 프리뷰 뷰 → 크롭 프레임 정규 좌표: `viewRectToCropNormalized`. 구도 엔진은 **크롭 프레임 기준 좌표만** 다룬다.
4. 크기를 알 수 없으면 `null` → 박스를 그리지 않는다.

크롭 프레임: 프리뷰 안에서 선택 비율(1:1, 4:5, 3:4, 9:16)의 가운데 정렬 최대 사각형(`computeCropRect`).

## 2. 취향 → 프로필 (`createProfileFromAnswers`)

| 선택 | 반영 |
|---|---|
| 촬영 대상 | detector 종류(인물·OOTD=얼굴, 음식=객체, 풍경=없음), 기본 세로 위치, 크기 표 |
| 구도 스타일 | 치우침 정도: 3분할=1/6(3분할선), 여백=0.22, 중앙·클로즈업=0.14 / 격자 종류 / 크기 보정 |
| 피사체 위치 | 목표 중심 `targetAnchor`의 방향, 여백 방향 `negativeSpace`(반대편) |
| 피사체 크기 | `targetSubjectScale {min, ideal, max}` (min/max = ideal ± 25%, OOTD ± 35%) |
| 비율 | 크롭 프레임 |
| 가이드 강도 | 격자(최소=끔), 피사체 박스(최소=숨김), 방향 화살표(자세히), ready 유지 시간(500/700/900ms) |
| 수평 안내 | 수평선 표시 + ready 조건에 수평 포함 |

크기 지표 `s = sqrt(가로비율 × 세로비율)` (크롭 프레임 대비).

| 모드 | 작게 | 보통 | 크게 | 기준 |
|---|---|---|---|---|
| 인물 | 0.16 | 0.26 | 0.40 | 얼굴 박스 |
| 음식·사물 | 0.32 | 0.50 | 0.70 | 주요 객체 박스 |
| OOTD | 0.07 | 0.10 | 0.14 | 전신 프레이밍에서의 얼굴 박스 |

인물은 얼굴을 중앙보다 위(y=0.38, 클로즈업 0.42), OOTD는 y=0.20에 둔다(사용자가 위/아래를 고르면 그 선택 우선).

## 3. 안내 엔진 (`GuidanceEngine`)

입력: 현재 시각, 피사체 관측(크롭 좌표·신뢰도·추적 ID·시각) 또는 없음, 기울기(도) 또는 없음, detector 사용 가능 여부.

1. **유효성**: 관측이 없거나 / `staleResultMs`(1000ms)보다 오래됐거나 / 신뢰도가 `minConfidence`(0.5) 미만이면 사용하지 않는다.
2. **유예**: 유효 관측이 없어도 `detectionGraceMs`(600ms) 동안은 직전 평활화 결과로 평가한다. 지나면 박스를 해제하고 `searching`(이전에 본 적 있으면 "피사체를 화면에 맞춰 주세요"). 저신뢰로 유실되면 `unavailable`.
3. **평활화**: 바운딩 박스 EMA, α=0.45. 추적 ID가 바뀌면 초기화. 같은 관측을 다시 평가할 때는 중복 적용하지 않는다.
4. **오차**: `dx = cx − tx`, `dy = cy − ty`, `s`.
5. **판정(히스테리시스)**
   - 위치: 맞기 전 `|dx|,|dy| ≤ 0.06`, 맞은 뒤에는 `0.09`를 넘어야 틀어짐.
   - 크기: `[min, max]`, 맞은 뒤에는 ±10% 여유.
   - 수평: 맞기 전 2°, 맞은 뒤 3.5°.
6. **안내 방향 우선순위**: 위치(오차가 큰 축) → 크기(가까이/멀리) → 수평.
   - 방향은 "피사체가 화면에서 이동해야 할 쪽"이다(예: 피사체가 목표보다 오른쪽이면 `left`).
   - 여백 프로필에서 여백 반대 방향으로 가야 할 때는 "오른쪽에 여백을 두세요" 형태의 문구를 쓴다.
7. **문구 깜박임 방지**: 새 방향이 `directionHoldMs`(250ms) 동안 유지되어야 전환.
8. **상태**
   - `searching`: 피사체 없음
   - `adjusting`: 안내 방향 있음
   - `almost`: 모두 맞음, 유지 시간 세는 중
   - `ready`: `holdDurationMs` 동안 연속으로 맞음 → 라임 색 + 체크 아이콘 + 문구 + (설정 시) 진동. **자동 촬영 없음**
   - `unavailable`: detector/센서를 쓸 수 없음 → 수동 가이드 안내
9. `alignment`(0..1) = `1 − (0.6·위치오차 + 0.4·크기오차)`. 내부 지표이며 화면에 점수로 표시하지 않는다.

풍경 모드: detector 없이 수평만 평가(수평 맞음 + 유지 → ready). 센서를 쓸 수 없으면 `unavailable` + 수동 가이드.

## 4. 수평 (`level.ts`)

- 가속도 센서의 중력 벡터에서 `roll = atan2(±x, |y|)`.
- 화면 평면 중력 성분이 35% 미만(기기를 눕힌 탑뷰 등)이면 `null` → 수평 안내를 하지 않는다.
- 축 부호는 플랫폼별로 반대다. **기울기 선이 도는 방향(부호)은 실기기 확인 대상**, 크기는 부호와 무관.

## 5. 촬영 확인 (`photo-quality.ts`)

네이티브가 촬영 파일을 긴 변 약 480px로 축소 디코딩해 계산한다.

| 항목 | 값 | 판정(초기값) |
|---|---|---|
| 노출 | 평균 밝기, 암부(<20/255) 비율, 명부(>245/255) 비율 | 평균<0.22 또는 암부>60% → 어두움 / 평균>0.80 또는 명부>35% → 밝음 |
| 선명도 | 라플라시안 분산 | <45 흐림, <130 보통, 그 이상 선명 |
| 수평 | 셔터 시점 센서 기울기 | ≤3.5° 맞음 |

참고 표시일 뿐 사진의 품질 점수가 아니다. 임계값은 실제 사진으로 보정해야 한다(미검증). 측정 실패 시 "확인 불가".
